# 장보기 가격 페이지 설계 (1차)

2026-11-02 작성. 이 문서는 정한 것을 한곳에 모은 것이다. 왜 그렇게 정했는지와 버린 대안은 `docs/decisions.md`의 같은 날 기록들에 있다. "(이 문서에서 처음 제안)"이라고 적은 것은 기록에 없고 이 문서를 쓰며 Claude가 더한 것이다. 사용자 검토 전이다.

## 1. 목적과 성공 기준

- 대형마트 안에서 가격표의 값이 적당한지 판단한다. 페이지는 품종별 KAMIS 단위 가격과 "평년보다 18% 비쌈 · 비싼 편" 같은 신호를 보여 주고, 비교는 사람이 눈으로 한다.
- 집에서 장보기 목록을 담아 두고, 마트에서는 그 목록을 보며 가격표와 비교한다. 목록에 없는 품목은 그 자리에서 검색한다.
- 나와 가족이 각자 자기 폰으로 쓴다. 목록은 폰마다 따로다.
- 1차 성공 기준(셋 다 만족해야 한다)
  1. 마트 안에서 인터넷이 안 돼도 마지막으로 받은 가격으로 열린다.
  2. 가족이 주소만 받고 설명 없이 쓴다.
  3. 평일마다 사람이 손대지 않아도 가격이 바뀐다.

## 2. 1차 범위

| 넣는 것 | 빼는 것(2차 이후) |
|---|---|
| 품종별 단위 가격과 신호, 30일 추이 | 가격표 값을 입력하면 판정해 주기 |
| 검색, 장보기 목록(폰마다), 개수 조절 | 가족 목록 공유 |
| 예상 총액(범위) | 장보기 기본 단위(예: 양파 1망) |
| 오프라인, 홈 화면 추가 | 중품 등급 |
| 샘플 모드(키가 없을 때) | 화면 자동 시험 |

## 3. 전체 구조

```
[GitHub Actions — 평일 저녁 1회, "지금 실행" 버튼도 있음]
  KAMIS API → 수집 스크립트(파이썬) → data/prices.json (계산이 끝난 값)
  → 바뀐 게 있을 때만 커밋·푸시 → GitHub Pages 배포

[GitHub Pages]
  화면 파일(HTML·CSS·JS, 빌드 없음) ── 읽기 ──→ data/prices.json

[핸드폰]
  화면 파일과 마지막 prices.json을 폰에 저장 → 인터넷이 없어도 열림
  장보기 목록은 폰 안(localStorage)에 저장
```

- 계산은 수집 스크립트에서 모두 끝낸다. 화면은 보여 주기와 목록 합계만 한다.
- 브라우저는 KAMIS를 직접 부르지 않는다(키가 화면 코드에 드러나기 때문).
- **Pages 배포는 Actions로 한다(이 문서에서 처음 제안).** Actions가 기본 토큰(GITHUB_TOKEN)으로 푸시한 커밋은 다른 워크플로를 깨우지 않는다는 GitHub 규칙이 있어서, 가격 커밋 뒤 배포가 안 일어날 수 있다. 그래서 수집 워크플로가 커밋한 다음 같은 워크플로 안에서 배포까지 한다. 사람이 코드를 푸시했을 때도 같은 워크플로가 배포만 한다.

## 4. 데이터 출처와 기준

| 항목 | 정한 것 |
|---|---|
| 출처 | KAMIS(한국농수산식품유통공사 농산물유통정보) Open API의 일별 소매가격 |
| 품목 | KAMIS 소매 조사 품목 전부(곡물·견과·건어물·가공식품 포함), 품종별로 따로. 약 140개로 짐작 |
| 등급 | 상품만 |
| 가격표와 비교할 값 | 전국 대형유통업체 조사처들의 평균. 대형유통만 골라낼 수 없으면 KAMIS 전국 평균으로 바꾼다 |
| 시기 비교(1주·1개월·1년 전, 평년) | KAMIS 전체 평균(전통시장과 대형유통을 섞은 값). 평년은 KAMIS가 낸 값을 그대로 쓴다 |

쓰는 API는 둘이다.

| 이 문서에서 부르는 이름 | KAMIS 이름 | 한 번 부르면 오는 것 |
|---|---|---|
| 전체 평균 API | `dailyPriceByCategoryList` | 부류 하나(6개 중)의 모든 품종: 당일, 1일 전, 1주 전, 2주 전, 1개월 전, 1년 전, 평년 값과 단위, 등급 |
| 가게별 값 API | `periodRetailProductList` | 품종 하나의 기간(최대 1년) 가게별 값: 지역, 가게 이름, 날짜, 가격 |

## 5. 수집

### 하루 흐름

1. 예약 실행은 Secrets에 키가 없으면 수집 스크립트를 돌리지 않고 "키 없음"을 남긴 채 정상으로 끝낸다. 수집 스크립트 자체는 키(환경변수)가 없으면 샘플 모드로 돈다(10절).
2. 전체 평균 API를 부류마다 한 번씩(6번) 불러 품종별 시기 비교 값과 단위를 받는다.
3. 가게별 값 API를 품종마다 불러 최근 31일치 가게별 값을 받는다.
4. 새 기준일(전체 평균 API가 돌려준 당일 날짜. **이 정의는 이 문서에서 처음 제안**)이 기존 `prices.json`의 기준일과 같으면(주말·공휴일) 아무것도 바꾸지 않고 끝낸다.
5. 6절 규칙으로 계산해 새 `prices.json`을 따로 다 만든 뒤, 기존 파일과 바꿔 넣는다.
6. 커밋·푸시하고 Pages에 배포한다.

### 실패할 때

- 호출이 실패하면 간격을 늘려 가며 3번까지 다시 한다.
- 일부 품종만 끝내 실패하면 그 품종은 기존 `prices.json`의 값을 그대로 남기고, 그 품종의 기준일도 옛 날짜로 둔다. **(이 문서에서 처음 제안)** 기존 값이 없는 품종이면 이번에는 뺀다. 전체 평균 API가 부류 하나만 실패하면 그 부류의 품종들을 같은 식으로 다룬다.
- 전체 평균 API가 끝내 실패하거나, 모든 품종이 실패하면 기존 파일을 그대로 두고 실행을 "실패"로 끝낸다. GitHub이 메일로 알린다.

### 품종 목록 파일

- 화면에 보일 이름과 KAMIS 코드(부류·품목·품종·등급)를 잇는 파일이다. 처음 요청의 "품목명 → KAMIS 코드 대응 파일"이 이것이다.
- 처음 한 번 KAMIS "품목 및 등급 코드표"와 전체 평균 API 응답에서 자동으로 뽑아 만들고, 저장소에 넣는다.
- 품종마다 화면 이름, KAMIS 코드, 조사 단위, 무게/개수 구분을 적는다. 이름을 고치거나 무게/개수 구분이 틀린 것은 이 파일에서 손으로 고친다.

## 6. 계산 규칙

| 값 | 규칙 |
|---|---|
| 대형유통 평균 | 그날 대형유통 가게 값들의 평균 |
| 조사처 수 | 그날 값이 있는 대형유통 가게 수 |
| 범위 | 그날 대형유통 가게 값을 값 순서로 세웠을 때 가운데 절반의 낮은 끝과 높은 끝(아래 4분의 1 지점과 위 4분의 1 지점). 조사처가 4곳보다 적으면 가장 낮은 값~가장 높은 값. **(이 문서에서 처음 제안)** 4분의 1 지점은 파이썬 `statistics.quantiles(값들, n=4, method="inclusive")`의 첫째·셋째 값으로 잡고, 범위는 조사 단위 기준과 단위 가격 기준 둘 다 낸다 |
| 단위 가격 | 무게로 조사한 품종은 100g당 값(예: 1kg 2,400원 → 100g당 240원). 개수로 조사한 품종은 그 단위 하나당 값(예: 1포기, 1마리. 계란 30구 → 1개당 250원). 원 단위로 반올림 |
| 시기 비교 % | (전체 평균 당일 − 전체 평균 비교 시점) ÷ 전체 평균 비교 시점 × 100. 화면에는 정수로 보인다 |
| 신호 | 평년 대비 %를 반올림하기 전 값으로 판단한다. +15% 이상은 "비싼 편", −15% 이하는 "싼 편", 그 사이는 "보통". 15%는 임시 기준이며 실제 데이터를 본 뒤 다시 정한다 |
| 30일 추이 | 최근 31일 가운데 값이 있는 날마다의 대형유통 평균 |
| 빼는 품종 | 최근 31일 동안 값이 하나도 없는 품종은 파일에 넣지 않는다 |
| 예상 총액 | 목록의 품종마다 (범위 낮은 끝 × 개수)를 더한 값 ~ (범위 높은 끝 × 개수)를 더한 값. 범위와 개수는 KAMIS 조사 단위 기준이다 |
| 값 없는 품목과 총액 | **(이 문서에서 처음 제안)** 목록에 있지만 지금 값이 없는 품종은 총액에서 빼고, 총액 줄에 "값 없는 품목 1개 제외"처럼 적는다 |

## 7. 화면용 파일(`data/prices.json`)

| 묶음 | 항목 |
|---|---|
| 파일 전체 | 기준일, 출처(KAMIS 또는 샘플), 만든 시각, 기준 설명(비교는 "전국 대형유통 평균", 시기 비교는 "KAMIS 전체 평균"), 비싼 편 기준(±15%) |
| 품종마다 | 품종 코드, 이름과 부류, 조사 단위와 무게/개수 구분, 대형유통 평균(조사 단위 값과 단위 가격), 조사처 수, 범위(조사 단위 기준과 단위 가격 기준), 시기 비교 %(1주·1개월·1년 전, 평년)와 신호, 30일 추이, 품종 기준일 |

크기는 140KB쯤으로 짐작한다(계산해 본 값은 아니다). Pages가 압축해 보내므로 실제로 받는 양은 수십 KB다.

## 8. 화면

화면 예시는 `.superpowers/brainstorm/`(git에 넣지 않음)의 `layout.html`, `card.html`, `search-detail.html`에 있다.

- **배치**: 한 화면이다. 맨 위에 기준일과 출처, 가운데에 내 목록, 그 아래에 예상 총액 줄, 맨 아래(엄지 자리)에 검색창이 늘 있다.
- **내 목록**: 품종마다 한 줄(이름, 단위 가격, 신호)이다. 개수가 2 이상이면 이름 옆에 "×2"를 붙인다. 철이 지나 값이 없어진 품종은 지우지 않고 회색 "지금 값 없음"으로 보인다. 줄을 누르면 상세 화면이다.
- **검색**: 검색어를 치면 목록 자리가 검색 결과로 바뀐다. 품목으로 묶고 그 아래에 품종을 한 줄씩 보인다. 줄 오른쪽 "＋ 담기"로 바로 목록에 넣는다(개수 1). 검색창의 ✕를 누르면 내 목록으로 돌아간다. **(이 문서에서 처음 제안)** 품목 이름이나 품종 이름에 검색어가 들어 있으면 결과에 나온다(예: "파" → 대파, 쪽파, 양파, 파프리카).
- **상세 화면**: 위에서 아래로 단위 가격과 조사 단위 값·조사처 수 → 대형마트 범위(단위 가격 기준) → 30일 그래프 → 요즘 시기(평년 대비 %와 신호, 1주·1개월·1년 전 %, "KAMIS 전체 평균 기준" 표시) 순서다. 맨 아래에 개수(−/＋), "목록으로" 버튼, "목록에서 빼기"를 둔다.
- **안내와 표시**
  - 목록이 비어 있으면 가운데에 "아래 검색창에서 품목을 찾아 ＋ 담기를 눌러 보세요".
  - 처음 열었을 때 맨 위에 한 번 "홈 화면에 추가하면 앱처럼 쓰고, 인터넷 없이도 열려요". 닫으면 다시 나오지 않는다.
  - 출처가 샘플이면 맨 위에 "샘플 데이터예요. 실제 가격이 아니에요" 띠.
  - 인터넷이 없을 때 맨 위에 "인터넷 연결 없음 · 11월 2일 값".
  - 품종 기준일이 파일 기준일과 다르면(일부 실패) 그 품종에 "어제 값"처럼 표시.

## 9. 오프라인과 목록 저장

- 서비스 워커(브라우저가 파일을 폰에 저장해 두는 기능)를 쓴다. 화면 파일은 저장해 둔 것을 먼저 쓰고, `prices.json`은 인터넷이 되면 새로 받고 안 되면 저장해 둔 마지막 파일을 쓴다. 화면 파일을 고치면 저장해 둔 묶음의 이름(버전)을 바꿔 폰이 새 파일을 받게 한다.
- 홈 화면 추가용 설정 파일(manifest)에 앱 이름, 아이콘, 세로 화면을 정해 둔다.
- 목록은 폰 안 저장 공간(localStorage)에 품종 코드와 개수만 저장한다. 가격은 늘 최신 `prices.json`에서 가져온다.
- 저장을 맡는 코드는 한 파일로 떼어 둔다. 화면은 그 파일의 함수(목록 읽기, 담기, 빼기, 개수 바꾸기)만 부르고, 함수는 결과를 나중에 돌려주는 방식(Promise)이다. 나중에 가족 공유로 바꿀 때 이 파일만 바꾼다.

## 10. 샘플과 키 전환

- 키가 없으면 수집 스크립트는 KAMIS 대신 저장소 안의 샘플 응답 파일을 읽는다. 샘플 응답은 KAMIS 문서의 응답 모양을 따르고, 응답 해석과 계산 코드는 실제 모드와 같다.
- 샘플 값은 지어낸 값이다(30일치, 대형유통 30곳쯤과 전통시장 몇 곳). 품목·품종 코드는 실제 KAMIS 코드표의 코드를 쓴다. 코드표(엑셀 첨부 파일)는 구현할 때 파일 이름과 크기를 알리고 허락을 받은 뒤 내려받는다.
- 키는 GitHub Secrets의 `KAMIS_CERT_KEY`, `KAMIS_CERT_ID`에 넣는다. 넣으면 다음 실행부터 코드 수정 없이 실제 데이터로 바뀐다.
- 실제 데이터가 들어간 뒤에는 샘플 모드가 `prices.json`을 덮어쓰지 않고 멈춘다.
- 내 컴퓨터에서 키로 시험할 때는 환경변수로만 넘긴다. `.env` 파일은 git에서 뺀다.

## 11. 확인 방법

- **수집 스크립트**: 인터넷 없이 도는 자동 시험(pytest). 응답 해석, 6절 계산 규칙 하나하나(경계값 포함: +15%는 비싼 편, +14.9%는 보통, 조사처 3곳이면 최저~최고), 값 없는 품종 빼기, 기준일이 같을 때 건너뛰기, 일부·전체 실패, 샘플 모드가 실제 파일을 덮어쓰지 않기.
- **화면**: Claude가 내 컴퓨터에서 서버를 띄우고 앱 안 브라우저를 휴대폰 크기(375px)로 열어 직접 확인한다. 검색 → 담기 → 개수 → 총액 → 상세 → 빼기, 빈 목록 안내, 샘플 띠, 인터넷을 끊었을 때 열리는지.
- **1차 성공 기준**: 사람이 확인한다. 실제 폰에서 홈 화면 추가 후 비행기 모드로 열기, 가족에게 주소만 주고 써 보게 하기, 키를 넣은 뒤 평일 사흘 연속 자동 커밋 확인(키가 오기 전에는 "키 없음" 정상 종료만).

## 12. 나눌 부분 (이 문서에서 처음 제안)

부분마다 하는 일이 하나이고, 다른 부분은 정해진 함수로만 부른다.

| 부분 | 하는 일 | 쓰는 것 |
|---|---|---|
| KAMIS 받기 | 실제 모드에서는 API를 부르고(다시 시도 포함), 샘플 모드에서는 샘플 파일을 읽는다. 둘 다 같은 모양의 응답을 돌려준다 | 키(환경변수), 샘플 파일 |
| 응답 해석 | KAMIS 응답을 품종별 값으로 바꾼다. 가게 이름으로 대형유통을 가려낸다 | KAMIS 받기의 결과 |
| 계산 | 6절 규칙. 입력과 출력이 숫자뿐이라 시험하기 쉽다 | 응답 해석의 결과, 품종 목록 파일 |
| 파일 쓰기 | 건너뛰기 판단, 일부 실패 때 지난 값 남기기, 샘플 덮어쓰기 막기, 새 파일 바꿔 넣기 | 계산 결과, 기존 `prices.json` |
| 화면 | 목록·검색·상세 그리기, 총액 합계 | `prices.json`, 목록 저장 |
| 목록 저장 | 9절의 함수들 | localStorage |
| 서비스 워커 | 9절의 오프라인 처리 | 화면 파일, `prices.json` |
| 예약 실행 | 평일 저녁 실행, "지금 실행" 버튼, 키 없음 처리, 커밋·푸시, Pages 배포 | 수집 스크립트 |

## 13. 사람이 할 일

- 키를 받으면 GitHub 저장소 설정의 Secrets에 `KAMIS_CERT_KEY`, `KAMIS_CERT_ID`를 넣는다.
- **(이 문서에서 처음 제안)** GitHub 저장소 설정에서 Pages의 출처를 "GitHub Actions"로 고른다(3절의 Actions 배포에 필요하다).
- 1차 성공 기준 확인(11절).

## 14. 아직 모르는 것

- 계란, 돼지고기, 닭고기 같은 축산물을 같은 기준(전국 대형유통 평균)으로 받을 수 있는지. KAMIS 조사대상품목 화면에서 계란·닭고기는 친환경 농산물 소매 목록에만 있었고, 돼지고기·소고기·우유는 없었다.
- 키를 받은 뒤 첫 실행에서 확인할 것: 가게별 값 API 응답에서 대형유통만 골라낼 수 있는지(`marketname`), 가게별 값 API를 품종 코드 없이 부를 수 있는지, 평년 값이 실제로 오는지, 품종별 조사 단위, KAMIS가 그날 값을 올리는 시각(예약 실행 시각을 이것으로 정한다), 하루 호출 한도.
