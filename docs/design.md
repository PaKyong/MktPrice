# 장보기 가격 페이지 설계 (1차)

2026-11-02 작성. 이 문서는 정한 것을 한곳에 모은 것이다. 왜 그렇게 정했는지와 버린 대안은 `docs/decisions.md`의 같은 날 기록들에 있다. "(이 문서에서 처음 제안)"이라고 적은 것은 기록에 없고 이 문서를 쓰며 Claude가 더한 것이다. 2026-11-02 사용자가 이 문서를 검토하고 그대로 확정했다(처음 제안한 것들 포함). 2026-11-03 화면 생김새를 "장보기 예상 영수증"으로 바꾸며 8·9·11·12절을 고쳤다(`docs/decisions.md`의 2026-11-03 기록들). 같은 날 화면의 중심을 "품목을 찾아 시세 보기 + 즐겨찾기"(증권 앱 느낌)로 다시 바꾸며 1·2·3·6·8·9·11·12절을 고쳤다. 장보기 목록, 개수, 예상 총액, 영수증 생김새는 뺐다. 같은 날 이마트 상품(한국소비자원 참가격)을 더하기로 하고 15절을 새로 쓰며 1·2·3·13·14절을 고쳤다. 2026-11-04 상세 화면의 가격 막대를 17절로 더했다.

## 1. 목적과 성공 기준

- 대형마트 안에서 가격표의 값이 적당한지 판단한다. 페이지는 품종별 KAMIS 단위 가격과 "평년보다 18% 비쌈 · 비싼 편" 같은 신호를 보여 주고, 비교는 사람이 눈으로 한다.
- KAMIS에 없는 완제품(라면, 과자, 냉동식품 등)과 고기는 이마트 상품으로 본다. 한국소비자원 참가격에서 이마트 값을 받아 상품마다 "평소 값"과 "행사 때 최저 값"을 보여 준다(15절).
- 자주 보는 품종은 즐겨찾기에 모아 두고 첫 화면에서 한눈에 본다. 마트에서는 즐겨찾기를 보거나 그 자리에서 검색해 가격표와 비교한다.
- 나와 가족이 각자 자기 폰으로 쓴다. 즐겨찾기는 폰마다 따로다.
- 1차 성공 기준(셋 다 만족해야 한다)
  1. 마트 안에서 인터넷이 안 돼도 마지막으로 받은 가격으로 열린다.
  2. 가족이 주소만 받고 설명 없이 쓴다.
  3. 평일마다 사람이 손대지 않아도 가격이 바뀐다. 이마트 상품은 한 달에 한 번, 참가격에 새 달 값이 올라온 뒤 첫 예약 실행에서 손대지 않아도 바뀐다(15절).

## 3. 전체 구조

```
[GitHub Actions — 평일 저녁 1회, "지금 실행" 버튼도 있음]
  KAMIS API → 수집 스크립트(파이썬) → data/prices.json (계산이 끝난 값)
  참가격 API(새 달이 있을 때만) → 수집 스크립트 → data/emart.json (15절)
  → 바뀐 게 있을 때만 커밋·푸시 → GitHub Pages 배포

[GitHub Pages]
  화면 파일(HTML·CSS·JS, 빌드 없음) ── 읽기 ──→ data/prices.json, data/emart.json

[핸드폰]
  화면 파일과 마지막 prices.json·emart.json을 폰에 저장 → 인터넷이 없어도 열림
  즐겨찾기는 폰 안(localStorage)에 저장
```

- 계산은 수집 스크립트에서 모두 끝낸다. 화면은 보여 주기만 한다.
- 브라우저는 KAMIS를 직접 부르지 않는다(키가 화면 코드에 드러나기 때문).
- **Pages 배포는 Actions로 한다(이 문서에서 처음 제안).** Actions가 기본 토큰(GITHUB_TOKEN)으로 푸시한 커밋은 다른 워크플로를 깨우지 않는다는 GitHub 규칙이 있어서, 가격 커밋 뒤 배포가 안 일어날 수 있다. 그래서 수집 워크플로가 커밋한 다음 같은 워크플로 안에서 배포까지 한다. 사람이 코드를 푸시했을 때도 같은 워크플로가 배포만 한다.

## 5. 수집

### 하루 흐름

1. 예약 실행은 Secrets에 키가 없으면 수집 스크립트를 돌리지 않고 "키 없음"을 남긴 채 정상으로 끝낸다. 수집 스크립트 자체는 키(환경변수)가 없으면 샘플 모드로 돈다(10절).
2. 전체 평균 API를 부류마다 한 번씩(6번) 불러 품종별 시기 비교 값과 단위를 받는다. 요청에는 날짜를 넣는다. 오늘 값이 없으면 하루씩 거꾸로 최대 7일까지 찾아 값이 있는 가장 최근 날을 쓴다(2026-11-03, 실제 서버는 날짜가 없으면 거절한다).
3. 가게별 값 API를 품종마다 불러 최근 31일치 가게별 값을 받는다.
4. 새 기준일(전체 평균 API가 돌려준 당일 날짜. **이 정의는 이 문서에서 처음 제안**)이 기존 `prices.json`의 기준일과 같으면(주말·공휴일) 아무것도 바꾸지 않고 끝낸다.
5. 6절 규칙으로 계산해 새 `prices.json`을 따로 다 만든 뒤, 기존 파일과 바꿔 넣는다.
6. 커밋·푸시하고 Pages에 배포한다.

### 실패할 때

- 호출이 실패하면 간격을 늘려 가며 3번까지 다시 한다.
- 일부 품종만 끝내 실패하면 그 품종은 기존 `prices.json`의 값을 그대로 남기고, 그 품종의 기준일도 옛 날짜로 둔다. **(이 문서에서 처음 제안)** 기존 값이 없는 품종이면 이번에는 뺀다. 전체 평균 API가 부류 하나만 실패하면 그 부류의 품종들을 같은 식으로 다룬다.
- 전체 평균 API가 끝내 실패하거나, 모든 품종이 실패하면 기존 파일을 그대로 두고 실행을 "실패"로 끝낸다. GitHub이 메일로 알린다.

### 품종 목록 파일

- 화면에 보일 이름과 KAMIS 코드(부류·품목·품종·등급)를 잇는 파일이다. 처음 요청의 "품목명 → KAMIS 코드 대응 파일"이 이것이다.
- 처음 한 번 KAMIS "품목 및 등급 코드표"와 전체 평균 API 응답에서 자동으로 뽑아 만들고, 저장소에 넣는다.
- 품종마다 화면 이름, KAMIS 코드, 조사 단위, 무게/개수 구분을 적는다. 이름을 고치거나 무게/개수 구분이 틀린 것은 이 파일에서 손으로 고친다.

## 6. 계산 규칙

| 값 | 규칙 |
|---|---|
| 대형유통 평균 | 그날 대형유통 가게 값들의 평균 |
| 조사처 수 | 그날 값이 있는 대형유통 가게 수 |
| 범위 | 그날 대형유통 가게 값을 값 순서로 세웠을 때 가운데 절반의 낮은 끝과 높은 끝(아래 4분의 1 지점과 위 4분의 1 지점). 조사처가 4곳보다 적으면 가장 낮은 값~가장 높은 값. **(이 문서에서 처음 제안)** 4분의 1 지점은 파이썬 `statistics.quantiles(값들, n=4, method="inclusive")`의 첫째·셋째 값으로 잡고, 범위는 조사 단위 기준과 단위 가격 기준 둘 다 낸다 |
| 단위 가격 | 무게로 조사한 품종은 100g당 값(예: 1kg 2,400원 → 100g당 240원). 개수로 조사한 품종은 그 단위 하나당 값(예: 1포기, 1마리. 계란 30구 → 1개당 250원). 원 단위로 반올림 |
| 시기 비교 % | (전체 평균 당일 − 전체 평균 비교 시점) ÷ 전체 평균 비교 시점 × 100. 화면에는 정수로 보인다 |
| 신호 | 평년 대비 %를 반올림하기 전 값으로 판단한다. +15% 이상은 "비싼 편", −15% 이하는 "싼 편", 그 사이는 "보통". 15%는 임시 기준이며 실제 데이터를 본 뒤 다시 정한다 |
| 30일 추이 | 최근 31일 가운데 값이 있는 날마다의 대형유통 평균 |
| 빼는 품종 | 최근 31일 동안 값이 하나도 없는 품종은 파일에 넣지 않는다 |

예상 총액은 2026-11-03에 화면에서 뺐다. 조사 단위 기준 범위는 총액에 쓰던 값이라 지금 화면은 쓰지 않지만, 수집은 그대로 두어 파일에 남는다.

## 8. 화면

2026-11-03에 화면의 중심을 "품목을 찾아 시세 보기 + 즐겨찾기"로 바꾸고, 생김새를 증권 앱의 관심 종목 목록처럼 바꿨다. 그 전의 장보기 목록, 개수, 예상 총액, 영수증 생김새는 뺐다. 시안은 같은 날 대화에서 그림으로 보고 정했다.

화면은 둘이다. 첫 화면과 상세 화면.

- **첫 화면**: 위에서 아래로
  1. 검색창: 맨 위에 있고, 화면을 내려도 위에 붙어 있다. 오른쪽 ✕는 검색어가 있을 때만 보이고, 누르면 검색어를 지워 첫 화면으로 돌아간다.
  2. 기준일 줄: 작은 흐린 글씨로 "2026.11.02 기준 · 출처 KAMIS"(샘플이면 "출처 샘플"). 샘플이면 그 아래 노란 띠로 "샘플 데이터 · 실제 가격 아님", 인터넷이 없으면 "인터넷 연결 없음 · 11월 2일 값".
  3. 홈 화면 안내: 처음 열었을 때 한 번 "홈 화면에 추가하면 앱처럼 쓰고, 인터넷 없이도 열려요" 쪽지와 "닫기". 닫으면 다시 나오지 않고, 이미 홈 화면 앱으로 열었으면 보이지 않는다.
  4. 즐겨찾기: 제목 "즐겨찾기" 아래에 넣은 순서대로 줄을 보인다. 비어 있으면 줄 대신 흐린 글씨로 "상세 화면에서 ☆를 누르면 여기 모여요".
  5. 전체 품목: 제목 "전체 품목" 아래에 부류 칸 줄("채소류 43" …)과 부류별 품종 줄. 지금 값이 있는 품종 전부를 보인다. 부류 순서는 채소류 → 과일류 → 수산물 → 식량작물 → 특용작물, 부류 안은 품목 가나다순이다(같은 품목 안 품종은 파일 순서). 부류 칸을 누르면 그 부류로 건너뛰고 칸을 칠한다. 칸 줄은 한 줄로 두고 옆으로 밀어 보며, 목록을 내려도 검색창 바로 아래에 붙어 있다.
- **검색**: 검색어를 한 글자라도 치면 즐겨찾기와 전체 품목 자리가 검색 결과로 바뀐다. 품목 이름이나 품종 이름에 검색어가 들어 있으면 나온다(예: "파" → 대파, 쪽파, 양파, 파프리카). 결과는 품목으로 묶지 않고, 전체 품목과 같은 모양의 줄을 같은 순서로 보인다. 위에 흐린 글씨로 `"파" 찾은 품종 6개`, 없으면 `"…"에 맞는 품목이 없어요. 다른 이름으로 찾아 보세요.` 목록을 손가락으로 내리기 시작하면 자판을 닫는다.
- **한 줄**(즐겨찾기, 전체 품목, 검색 결과 공통). 줄 어디를 눌러도 상세 화면으로 간다.
  - 왼쪽: 이름. 품종 이름에 품목 이름이 들어 있으면 품종 이름만 쓴다("양파", "대파", 그 밖에는 "사과 후지"). 그 아래 작은 흐린 글씨로 단위("100g당", "1개당")를 쓰고, 신호가 싼 편이면 빨간 "싼 편", 비싼 편이면 파란 "비싼 편"을 붙인다. 품종 기준일이 파일 기준일과 다르면(일부 실패) "11월 1일 값"도 붙인다.

## 9. 오프라인과 즐겨찾기 저장

- 서비스 워커(브라우저가 파일을 폰에 저장해 두는 기능)를 쓴다. 화면 파일은 저장해 둔 것을 먼저 쓰고, `prices.json`은 인터넷이 되면 새로 받고 안 되면 저장해 둔 마지막 파일을 쓴다. 화면 파일을 고치면 저장해 둔 묶음의 이름(버전)을 바꿔 폰이 새 파일을 받게 한다. 2026-11-03 추가: 새 화면 파일을 다 받아 서비스 워커가 자리를 잡으면 화면을 한 번 다시 연다(처음 설치할 때는 빼고). 이렇게 안 하면 다음에 열 때까지 옛 화면이 남는다.
- 화면이 다시 보일 때(다른 앱에서 돌아올 때, 홈 화면 앱을 다시 띄울 때) `prices.json`을 새로 받는다. 만든 시각이 같거나 못 받으면 지금 화면을 그대로 둔다.
- 홈 화면 추가용 설정 파일(manifest)에 앱 이름, 아이콘, 세로 화면을 정해 둔다.
- 즐겨찾기는 폰 안 저장 공간(localStorage)에 품종 코드와 이름만 넣은 순서대로 저장한다. 이름은 철이 지나 값이 없어져도 보이게 하려고 둔다. 가격은 늘 최신 `prices.json`에서 가져온다.
- 2026-11-03 전에 담아 둔 장보기 목록이 폰에 있으면, 처음 열 때 그 품종들을 담은 순서대로 즐겨찾기로 옮기고(개수는 버린다) 옛 목록은 지운다.
- 저장을 맡는 코드는 한 파일로 떼어 둔다. 화면은 그 파일의 함수(즐겨찾기 읽기, 넣기, 빼기)만 부르고, 함수는 결과를 나중에 돌려주는 방식(Promise)이다. 나중에 가족 공유로 바꿀 때 이 파일만 바꾼다.

## 10. 샘플과 키 전환

- 키가 없으면 수집 스크립트는 KAMIS 대신 저장소 안의 샘플 응답 파일을 읽는다. 샘플 응답은 KAMIS 문서의 응답 모양을 따르고, 응답 해석과 계산 코드는 실제 모드와 같다.
- 샘플 값은 지어낸 값이다(30일치, 대형유통 30곳쯤과 전통시장 몇 곳). 품목·품종 코드는 실제 KAMIS 코드표의 코드를 쓴다. 코드표(엑셀 첨부 파일)는 구현할 때 파일 이름과 크기를 알리고 허락을 받은 뒤 내려받는다.
- 키는 GitHub Secrets의 `KAMIS_CERT_KEY`, `KAMIS_CERT_ID`에 넣는다. 넣으면 다음 실행부터 코드 수정 없이 실제 데이터로 바뀐다.
- 실제 데이터가 들어간 뒤에는 샘플 모드가 `prices.json`을 덮어쓰지 않고 멈춘다.
- 내 컴퓨터에서 키로 시험할 때는 환경변수로만 넘긴다. `.env` 파일은 git에서 뺀다.
